# 运动遥控器 — 我们的示范

众多例子中的一个。请勿重复使用其故事、弧线、镜头、道具或时间安排。

示范：*冻结帧*（定格，54.4 s）·`telestrator.mp4`·源在[`demo/`](demo/)

伊斯坦布尔，2019 年 2 月 25 日：半场结束时贝西克塔斯 3-0 领先费内巴切；费内巴切配乐在 12 分钟内打进三球，并以 3-3 战平。一个虚构的分析节目*定格冻结框架*，逐个进球地反击，每个进球都有自己的技术和配乐栏翻转 3-0 → 3-1 → 3-2 → 3-3：第 55 分钟的进球在比赛中从右侧传球时被冻结；第61分钟的头球被冻结在两个并排的摄影机角度，然后被VAR检查盖章；第67分钟扳平比分——决定性的一球——观看了直播、倒带和冻结三次（半解围的球，没有人走出去，接球后0.84秒从禁区外射门），然后从反向回放中看到。最后，打击框架变平成一个自上而下的板，所有三个镜头位置都落在上面：两个是近距离镜头，一个是 27 米远镜头。数据卡重复计数的数字；英雄的分钟和名字结束了它。

这是一份非官方的粉丝分析，由广播公司本身在 CC BY 下发布的真实广播片段（beIN SPORTS Türkiye，在其经过验证的 YouTube 频道上；一个来自 Wikimedia Commons 的剪辑）、一张 CC BY 照片和一张 CC0 照片制成。该剧纯属虚构；在体育界，俱乐部和联盟并没有制定或认可它。每个事实都在[`demo/FACTS.md`](demo/FACTS.md)中引用；许可证检查位于 [`demo/SOURCES.md`](demo/SOURCES.md) 中。

CC BY 依据的是广播公司自己在 YouTube 上的许可声明（2026 年 10 月 21 日检查；`demo/tools/license-evidence.json` 中的证据）；我们看不到从联赛、俱乐部到转播商的版权链。许可证允许在此处托管具有完整归属的影片，但重新上传到视频平台仍可能通过 Content ID 进行匹配。以这种风格为您自己的主题制作的影片应该使用您自己的素材，或者您已以相同方式检查其许可证的素材。

<a id="story--structure"></a>
## 故事与结构

形状：按时间顺序进行深入分解，然后进行总结。斯汀和比赛记录卡（0-5.2 秒）将比分定为 0-3，并锁定了下半场的三个进球。目标一 (5.2–10.6) 和目标二 (10.6–17.8) 是轻型创作方案，因此第三个目标保留了完整的语法 (17.8–36.8)。 镜头地图 (36.8–42.6) 是崩溃后唯一的新想法：三个人被击中的地方。数据卡 (42.6–47.0)、67' 石板 (47.0–49.6) 和片尾卡 (49.6–54.4) 关闭。

格式花费，每一次都是为了一个新的事实：显示刺痛；带有进球时间线和标记括号的比赛记录卡；现场演奏并配有解说文字记录；比赛中冻结；双角度分屏定格； VAR 印章； 配乐-杆翻转（三个）；磁带倒带；三个聚光灯冻结有环、红色空间补丁、青色链接线、跟踪框线；带有跑步轨迹环的慢动作；帧计数秒表；球状彗星；具有自己的冻结功能的反向重播；透视图展平为镜头地图；带宝丽来的数据卡；英雄石板； 片尾卡。

<a id="score-structure"></a>
## 配乐结构

- 120 BPM，E 小调，采样乐队：MuldjordKit 鼓、电贝斯、断奏小号和长号、定音鼓、圆号、大提琴、钟琴。
- 凹槽在每个播放片段的开头重新开始（在记录卡和数据卡中充满，在现场播放时低，因此评论领先，在慢速播放和分屏中半场）。每次定格都是铜管刺击+定音鼓+重击+快门，然后只有踩镲：鼓随着画面停止。
- 目标：每个配乐-bar 翻转上带有碰撞和钟琴的大铜管和弦； VAR 标记落在低音定音鼓、长号和撞音上。
- 镜头地图：切入时刺伤，压平下的定音鼓卷楼，板稳定后第二次刺伤，钟琴 B–D–E 作为三排着陆，然后是半场凹槽。
- Slate 和片尾卡：大和弦，圆号和大提琴，E 小调，两声钟琴敲击，随着画面逐渐淡出。
- 自然的声音：广播员的解说和现场比赛中全场观众的解说，低传人群的床被冻结，球门的轰鸣声与球门框架对齐。
- 语音：Kokoro `bm_george`，8线，速度1.1；声音的拼写名称（“Zayits”、“Saduk”），字幕中的真实拼写。

## 调色板和道具

- 黄色`#FFD400`（我们跟随的球队，球），青色`#3FD8FF`（对手），红色`#FF3B30`（空格），粉笔`#F4F1E8`，板`#0C1411`。
- 类型：Noto Sans SC 500 / 700 / 900、Barlow Condensed 600 / 800 Italic、IBM Plex Mono 500（`demo/fonts/` 中的 OFL 子集）。
- 展示包装“定格FREEZE FRAME”（虚构）：刺、角虫三种模式，配乐条，黄色斜擦。

## 端卡

从 49.6 秒开始，保持到 54.1，然后用图片剪切为黑色：“定格”（150 px）、“定格”（黄色）、一条细尺、“SPORTS TELESTRATOR·体育战术板”、“LemoLab × Claude Opus 5.5”，然后是五行字幕：广播公司的 CC BY 视频及其带有标题和许可证的 Commons 剪切、所做的更改、CC BY 照片、CC BY 鼓组和带有声音的 CC0 源。 “LemoLab × Claude Opus 5.5”签名仅属于该库的示范；用户的影片不带有 LemoLab 积分，也没有该卡的副本。

<a id="build-notes"></a>
## 构建笔记

```
demo/
  index.html              the page: segments, one function per format, tracking keyframes (TRK), GOALS, TEXTS for readcheck
  timeline.json           segments (clip, source frame ranges) and voice lines — shared by page, .srt and mix
  audio/lines.json        narration (Kokoro, with phonetic names and expected ASR)
  tools/fetch_sources.sh  downloads raw/ (~55 MB: Commons clip and photos, the broadcaster's CC BY video via uvx yt-dlp)
  tools/prep.sh           clips → 1920 JPEG sequences a/ b/ c/ (deblock, lanczos 1.5×, unsharp, grade), photos, match sound
  tools/pitch.json        pitch points per shot frame     tools/homography.py   → assets/pitch.json (matrices, shot positions)
  tools/mix.py            score, foley, voice, match sound, ducking → out/mix.wav
  tools/cues.py           timeline.json → audio/cues.json     tools/fonts.py   OFL subsets
  tools/final_check.sh    loudness, black frames, speech-to-text of the final mix
  tools/footage.py        finding and logging footage (see STYLE.md §10)     tools/license-evidence.json
  FACTS.md, SOURCES.md, SOURCES.jsonl, CREDITS
```

`sh demo/build.sh`（使用 `setup.sh deps voice music` 设置的库，示例包 freepats / vsco2ce / vcsl 和 `uv`）：源 → 帧 → 同形异义 → 字体 → 语音 + 语音检查 → 提示 → 阅读检查 → 渲染（1,632 帧，30 fps）→ 混合 → .srt → 主控（−14） LUFS，颗粒 2) → 海报和风格定帧（13.6 秒，双角度定格） → 最终检查。 `?dbg=1` 绘制跟踪点； `?nosub=1` 隐藏字幕。

示范特定的选择和陷阱：前两个目标来自广播公司的完整摘要，结果是 Commons 剪辑的来源（其文件页面引用了视频），因此所有素材都是一个 CC BY 版本；共享页面没有许可证审查标记，因此在视频页面本身上检查了许可证（已验证频道，CC BY 字段），请参阅 `demo/SOURCES.md`。消息来源对第一个进球的助攻（瓦尔布埃纳 vs 迪拉尔）意见不一，因此影片两者都没有提及，并显示“从右侧数第 17 号”；官方进球列表（55′/61′/67′）胜过比赛报告中的 62′ 和 66′。一份报告中的“远角”说法与录像相矛盾，因此没有提及第三个球门的角球。分屏窗口首先以未剪辑的方式滑入，并显示了几帧广播公司的 URL；现在，每个窗口都被剪切到源坐标中的切片。 VAR印记在球越线之前首先落地；该航段被加长，因此在 F057 之后着陆。记录卡、镜头地图、数据卡和片尾卡被加长（不减慢），直到它们携带的每一行都通过了读取检查。
